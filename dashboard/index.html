👋 What is this, and how do I use it?

collapse ▴

This is a multi-agent digital foresight factory running locally on your machine. It ingests raw signals (research, regulation, releases, incidents, M&A), enriches them, clusters them into storylines, drafts decision-relevant insights, and publishes briefs after human approval. Every output is traceable back to source.

Trigger ingestion

Click ▶ Trigger demo in the header. Agent b1.ingestion reads 18 sample signals. Watch the Pipeline stages below light up as each agent fires — events stream on the right.

2

Review the insights

After ~1 second, drafts appear in Insights queue. Each is built from a cluster of related signals and shows confidence, time horizon, and recommended actions. Click any title to read the full draft.

3

Approve to publish

Click Approve → on a draft. The policy gate (a1.policy) re-checks it, then b6.publish writes a Markdown brief to data/products/. The Published stage counter ticks up.

📖 Glossary — the key concepts in one place

expand ▾
Signal
A single piece of raw content from a source — a headline + body. Has a hash, source, URL, fetched timestamp. Stored immutably in the Knowledge Store.
Enrichment
Adding structure to a signal: summary, named entities (ORG/TECH/GEO/PERSON), taxonomy labels, signal type (regulation / research / incident / funding / release / patent).
Score
Relevance, novelty, urgency, impact — each 0–1. Plus a 2–3 bullet rationale for why this matters for The Company.
Cluster
A group of related signals forming a storyline. Grouped here by primary taxonomy + similarity. Has a label, descriptor, burst score, and updated-at.
Insight
A decision-relevant draft built from a cluster: what happened, evidence (citations), implications, time horizon, uncertainties, confidence level, recommended actions. Has two views: Exec one-pager + Analyst detail.
Approval gate
The human-in-the-loop checkpoint: insights only become approved when a reviewer clicks Approve. Hardcoded by a0.orchestrator + re-validated by a1.policy.
Product
A published artifact (Markdown brief here, in production: SharePoint page / Teams card / weekly email). Carries trace metadata back to insight → cluster → signals → raw source.
Agent
A small, single-responsibility component implementing the BaseAgent contract: subscribe to event topic(s), handle one event, emit downstream events. Versioned for traceability.
Event
A typed message on the bus. Every transition between stages is an event. Drives the entire pipeline asynchronously — no agent calls another directly.
Event bus
The publish/subscribe backbone. In the prototype: in-process Python pub/sub. In Azure: Azure Service Bus topics.
Knowledge Store
Three things stitched together: Blob for raw artifacts (immutable), structured store for signals/clusters/insights, vector index for similarity search + retrieval. Azure: Blob + Cosmos DB + AI Search.
Tier 0–3
Tier 0: control plane (4 agents, stable, trusted). Tier 1: production line (6 agents, the pipeline). Tier 2: intelligence upgrades (5 agents — credibility, red team, trajectory, scenarios, impact — fire on demand). Tier 3: domain pods (compose 0–2 for a specific domain).
